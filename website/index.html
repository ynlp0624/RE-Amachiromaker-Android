特性

原生该有的样子

不是把网页塞进浏览器控件，而是用安卓自己的零件重做了一遍。

原生 Compose 界面

标签页、贴图网格、色板、对话框全部由 Kotlin + Jetpack Compose 绘制，跟系统主题、手势、旋转保持一致。

完全离线

32 MB 素材随安装包一起走，安装后无需联网即可使用；安装包内没有申请 INTERNET 权限。

分层 PSD 导出

每个部位写成一个独立图层，带图层名与坐标，Photoshop、Krita、GIMP、Photopea 都能继续编辑。

换色系统

同一款贴图自带多套配色，圆形色板点一下就换；发色、瞳色、背景色都是同一套机制。

预设互通

搭配可导出成 JSON，也能直接载入网页版导出的预设，格式完全一致。

保存到相册

600 × 600 的成品图写进 Pictures/Amachiromaker/，相册应用里立刻能看到。

    隐藏页 · 踩坑实录

    这一路上踩过的坑

    从把这个网页包变成安卓应用，到把它发到四个下载源，下面这些是实际踩过的每一个坑，按类别整理，一条没删。

    安卓构建

    密钥文件找不到

    Keystore file 'app/keystore/local.jks' not found

    Gradle 里的 file() 是相对模块目录解析的，而密钥放在项目根目录。

    改成 rootProject.file("keystore/local.jks")

    那个「没有传 loader 参数」

    No value passed for parameter 'loader'

    Kotlin 的尾随 lambda 只能对应最后一个参数，而 loader 被写在了中间。

    把 lambda 参数挪到参数表最末尾

    两个 items 打架

    Argument type mismatch: List<LayerItem> but Int was expected

    网格用 LazyVerticalGrid 的 items，横向滚动用 LazyRow 的 items，同名不同包，编译器挑错了那个。

    用 import ... as gridItems 起别名区分

    release 卡在 lint 下载

    Could not download lint-31.6.1.jar ... Read timed out

    打包 release 会先跑 lint，而 lint 工具包不在缓存里，需要现场去 dl.google.com 拉，结果超时。

    lint { checkReleaseBuilds = false }，本地打包不需要它

    图层与渲染

    项圈被头发「穿过去」了

    项圈两端凭空消失，像被垂发切断

    原站数据里项圈排在衣服之后，改成压在衣服下之后，又被侧发（横髪）挡住两端——逐层拆解才定位到。

    最终顺序：项圈在头发之上、衣服之下，露脖衣服完整可见，高领衣服仍自然遮住

    项圈浮在高领衣服外面

    项圈看起来像系在衣服领子上

    原站把「チョーカー」排在「服」之后，于是项圈永远画在衣服最上层。

    重排绘制顺序（预览、PNG、PSD、SVG 四处同步）

    预览有点发虚

    600px 的图在手机上被撑到 900 物理像素

    ContentScale.Fit 会放大位图，重采样质量又一般。

    加 FilterQuality.High，缩放更平滑

    追加发的颜色不对劲

    选蓝发，追加发却是白的

    「+髪」这个部位的素材本身就是浅色系，色板里没有能匹配蓝发的档位。

    结论：不选它（记录在案，属数据本身的限制）

    袖的位置差点误判

    看上去像"胸前凭空一块布"

    肉眼看像在胸口，实际量了非透明区域才发现它在画布底部（y=531~599）。

    顺序没错，属于袖子该在的位置，保留

    一个部位缺了一种颜色

    後ろ髪 itmId=1211336 只有 9 种颜色（其他款都是 10 种）

    上游数据本身的缺口，不是移植造成的。

    记录在案；864 个素材文件本身零缺失

    素材与版权

    衣服凭空多出黑描边

    矢量化之后，干净的素色上衣长出了轮廓线

    插画是软渐变笔触，矢量化算法会把它理解成"色块 + 轮廓"，把柔和过渡描成硬边。

    放弃矢量化素材；改为保留原图 + 新增 SVG 分层导出

    那包素材不能发

    差点把 1111 张贴图打包成 Release 附件

    图片版权归画师所有，"应用整体分发"和"素材单独打包再分发"是两回事。

    素材包立即撤除；仓库与所有发行附件都不含素材

    矢量化的假描边（同上）与本条合并说明

    另一条教训：位图素材放大只能"补细节"，无法真的无损。AI 超分能提升观感，但会轻微强化线条。

    决定：素材保持原样，把无损需求交给 SVG 分层导出

    工具链的坑

    双引号被吞掉

    bash: 未预期的记号 "(" 附近有语法错误

    PowerShell 往 ssh 传内联脚本时会把引号吃掉，脚本到了远端已经变形。

    脚本改走 base64：echo <b64> | base64 -d > /tmp/x.sh

    脚本被撕成两行

    chown: 无效的选项 -- e

    在 PowerShell 双引号里写 \$VAR，反斜杠不是转义符，变量被展开成空，行尾只剩一个 \ 把命令接到下一行。

    改用占位符替换，或直接单引号 here-string

    中文全变乱码

    图层名读出来是「鑳屾櫙」

    Windows PowerShell 5.1 的 Get-Content 默认按 GBK 读，而文件是 UTF-8。

    显式指定编码读一遍，文件本身没坏

    JSON 里的引号没了

    Problems parsing JSON / 400

    两层原因：--data 传 JSON 时引号被 PowerShell 吞；写文件时又带了 BOM。

    写成不带 BOM 的文件，再用 --data-binary @file

    npm 被执行策略拦下

    无法加载文件 npm.ps1，因为在此系统上禁止运行脚本

    PowerShell 的执行策略挡住了 .ps1 包装脚本。

    直接调 npm.cmd

    批处理一个文件都没输出

    0.3 秒跑完，输出目录是空的

    不是工具的问题——管道里加了 Select-Object -First N，输出被截断后子进程被连带终止。

    改成 *> $null 丢弃输出，别截断

    PSD 头读出来是 88

    600 像素的图，解析出来宽高都是 88

    PowerShell 的 -shl 会保持左侧操作数的类型，byte 左移 8 位直接溢出成 0。

    改用第三方 PSD 解析器复核，结构完全正确

    发布与网络

    代码推不上去

    fatal: Recv failure: Connection was reset

    git 协议在传输中被重置；换成"用户名 + 令牌"仍被拦。

    改走 REST API 推送：blob → tree → commit → ref（空仓库要先种一个 commit）

    GitCode 的附件传不上去

    attach_files → 404

    它不是一步上传：要先取一个带签名的上传地址，再 PUT 上去，还得带上三个 x-obs 头。

    按两步流程走通，39 MB 上传只要 11 秒

    测速读不到数据

    GitCode 节点永远测不出速度

    它的 CDN 不返回跨域头，浏览器拿不到字节数。

    样本大小已知，于是只计时、用「512KB ÷ 耗时」反推

    同一批机器差 7 倍

    srv2 只有 40 KB/s，srv3 却跑到 260 KB/s

    不是配置问题，是线路质量。

    三个节点实测后把站点迁到最快那台，并把测速写进下载器

    套 CDN 反而变慢

    CF 代理 55 KB/s < 直连 260 KB/s

    一开始以为"直连被墙"，实测发现只是临时网络波动。

    改回官方直连，代理降为备选节点
